# Теория простыми словами

[English version](../en/theory.md)

Пакет отвечает на два вопроса о виртуальной машине (ВМ), потребление памяти
`x_n` которой меняется во времени: как долго её можно не наблюдать и не начался ли
рост потребления. Ответы опираются на мартингалы — «честные» игры. На этой странице
объяснены идеи; выводы есть в статье.

## 1. Честная игра и супермартингал

Представьте игрока, который ставит на монету: орёл приносит единицу, решка её
забирает. В среднем капитал не меняется — это мартингал. Игра, невыгодная в среднем,
— супермартингал. Пусть потребление памяти в спокойном режиме не растёт в среднем.
Тогда оно ведёт себя как супермартингал: зная прошлое, ожидаемое следующее изменение
не положительно.

```text
E[x_n - x_{n-1} | прошлое] <= 0          допущение А2, спокойное потребление
|x_n - x_{n-1}| <= c                     допущение А1, ограниченное изменение за шаг
```

## 2. Интервал мониторинга: сколько можно ждать

Свободный запас `R` исчерпан, если потребление выросло на `R` за интервал. Для
супермартингала с ограниченными шагами неравенство Азумы–Хёфдинга (формула (5))
говорит, что рост остаётся небольшим с высокой вероятностью, и типичный рост
растёт как `c sqrt(n)`, а не `c n`:

```text
P(рост на R и более за n шагов) <= exp(-R^2 / (2 n c^2))        формула (5)
```

Решая относительно наибольшего `n`, при котором эта вероятность не больше `delta`,
получаем интервал `n_A` формулы (7). Худший случай, когда каждый шаг растёт на `c`,
даёт детерминированный интервал `n_0 = ceil(R / c) - 1` формулы (8). Пакет берёт
больший из двух, ограничив его `n_max`, как в формуле (9).

| Запас R, МБ | c, МБ/с | Интервал, с (delta = 0,01) |
|---|---|---|
| 512 | 20 | 71 |
| 1024 | 20 | 284 |
| 512 | 50 | 11 |

Если `R <= c`, интервал равен `0`: один шаг уже может исчерпать запас.

## 3. Ставки против роста

Чтобы заметить начало роста, пакет делает ставки против него. Воображаемый игрок
ставит долю `lam` капитала на изменение на каждом шаге, нормированное через `c` к
отрезку [-1, 1]. Если роста нет, капитал не может систематически расти. Если
потребление растёт, капитал растёт.

```text
K_0 = 1,    K_n = K_{n-1} (1 + lam Y_n),    Y_n = изменение / (n c), обрезано до [-1, 1]   формула (11)
тревога, когда K_n >= 1 / alpha                                                          формула (12)
```

Неравенство Вилля говорит, что неотрицательный супермартингал, начинающийся с 1,
когда-либо достигает `1/alpha` с вероятностью не выше `alpha`. Это верно при любом
числе проверок и при проверках, назначенных по прошлому. Классический тест с фиксированной
выборкой теряет эту гарантию при повторном применении. Поэтому детектор можно читать в
нерегулярные моменты, как того требует планировщик.

Капитал хранится как логарифм `ln K`. Произведение многих множителей после нескольких
часов покоя обращается в ноль, и детектор перестал бы реагировать.

## 4. Долгий покой и вариант CUSUM

В долгом спокойном периоде капитал одиночной ставки уходит к нулю, потому что ставка
в среднем проигрывает. При начале роста детектору сначала нужно выбраться из этой ямы,
и задержка растёт. Формула (14) устраняет это статистикой типа CUSUM, которая никогда
не опускается ниже `1 - lam`:

```text
C_n = max(C_{n-1}, 1) (1 + lam Y_n)                                                      формула (14)
```

Гарантия другая: среднее время до ложной тревоги не меньше порога `A`, а не
вероятность. Порог `1e5` шагов означает примерно одну ложную тревогу в среднем раз в
28 часов при шаге в одну секунду.

## 5. Дополнения сверх статьи

* **Смесь ставок** (`MixtureGrowthDetector`). Усредните капиталы ставок с несколькими
  долями `lam` с равными весами. Каждая ставка — тестовый мартингал, и их среднее
  тоже. Гарантия Вилля сохраняется, и `lam` выбирать не нужно. Цена — штраф около
  `log(9) = 2,2` в логарифме капитала для девяти ставок. Веса по умолчанию равные;
  любые фиксированные веса с суммой 1 допустимы, и тогда штраф за ставку `j` равен `log(1/w_j)`.
* **Субгауссовы ставки** (`SubGaussianGrowthDetector`). Вариант более раннего кода,
  основанный на границе Азумы–Хёфдинга. Одно обновление меняет капитал на величину,
  растущую с `sqrt(n)`, что помогает, когда проверки редкие.

## 6. Несколько ВМ

Если `m` ВМ делят риск `delta`, каждой даётся риск `delta / m`. По неравенству Буля
вероятность того, что какая-либо ВМ исчерпает запас до своей следующей проверки, не
больше `delta`. Так работает `FleetMonitor(n_vms=m, delta=...)`.

## 7. Что нужно гарантиям

Гарантии верны, если выполнены допущения А1 и А2. Проверьте их на данных командой
`azarovo-martingale analyze`: долю приращений выше `c`, среднее приращение в спокойном
режиме и его автокорреляцию. Слишком малое `c` делает интервал слишком длинным, а дрейф
в спокойном режиме повышает частоту ложных тревог выше `alpha`. Отчёт показывает оба
эффекта.
